تمرین ۱

تحلیل هوشمند Review محصول

فرض کنید می‌خواهید برای یک فروشگاه آنلاین، سیستمی بسازید که Review مشتریان را به‌صورت خودکار تحلیل کند.

تابعی به نام زیر ایجاد کنید:

analyze_review(review: str)

که یک Review فارسی دریافت کرده و اطلاعات زیر را استخراج کند:

  • احساس کلی مشتری: positive / negative / neutral
  • امتیاز تقریبی از ۱ تا ۵
  • آیا مشتری احتمالاً محصول را پیشنهاد می‌کند یا خیر
  • مهم‌ترین نکات مثبت
  • مهم‌ترین نکات منفی
  • یک خلاصه کوتاه از Review

الزامات فنی

  • مدل را با init_chat_model ایجاد کنید.
  • Prompt را با ChatPromptTemplate بسازید.
  • برای خروجی یک Pydantic BaseModel تعریف کنید.
  • از with_structured_output استفاده کنید.
  • Review را با Delimiter از دستور Prompt جدا کنید.
  • در System Prompt نقش مدل را مشخص کنید.
  • محدودیت‌های خروجی را شفاف و دقیق بیان کنید.

نکته Prompt Engineering

  • Role
  • Clear & Specific Instructions
  • Delimiter
  • Output Format
  • جلوگیری از حدس زدن اطلاعاتی که در Review وجود ندارند.

حداقل ۵ Review مختلف را تست کنید؛ از جمله Reviewهای مثبت، منفی، خنثی و Reviewهایی که اطلاعات ناقص دارند.

رفرنس: 03_02-Guidelines-for-Prompting.ipynb، 03_06-NER.ipynb و 04_01-Models_Messages_StructuredOutput.ipynb
تمرین ۲

دستیار هوشمند پردازش رزومه

فرض کنید یک شرکت هر روز تعداد زیادی رزومه دریافت می‌کند و می‌خواهد اطلاعات اولیه آن‌ها را به‌صورت ساختاریافته استخراج کند.

تابعی به نام زیر بنویسید:

extract_resume_info(resume: str)

سیستم باید از متن رزومه این اطلاعات را استخراج کند:

name
email
phone
location
education
skills
years_of_experience
job_titles
programming_languages

همچنین یک فیلد به نام summary داشته باشید که در چند جمله سابقه فرد را خلاصه کند.

الزامات فنی

  • init_chat_model
  • ChatPromptTemplate
  • Pydantic
  • with_structured_output

الزامات Prompt

  1. نقش مدل را به‌عنوان Resume Information Extractor مشخص کنید.
  2. متن Resume را با delimiter مشخص کنید.
  3. به مدل بگویید اطلاعاتی را که در Resume وجود ندارد حدس نزند.
  4. برای هر فیلد توضیح واضحی ارائه کنید.
  5. برای skills و programming_languages خروجی لیستی در نظر بگیرید.
  6. از مدل بخواهید summary را فقط بر اساس اطلاعات موجود در Resume تولید کند.

بخش اضافه

یک Resume فارسی و یک Resume انگلیسی را تست کنید. سپس یک Resume ناقص بدهید که مثلاً شماره تلفن یا سابقه کاری نداشته باشد و رفتار سیستم را بررسی کنید.

رفرنس: 03_02-Guidelines-for-Prompting.ipynb، 03_06-NER.ipynb و 04_01-Models_Messages_StructuredOutput.ipynb
تمرین ۳

تبدیل متن خام مشتری به Ticket پشتیبانی

فرض کنید متن زیر از چت مشتری وارد سیستم پشتیبانی شده است:

«سلام، از صبح نمی‌تونم وارد حسابم بشم. هر بار رمزمو می‌زنم خطای Authentication failed میده. خیلی عجله دارم چون باید امروز گزارشمو ارسال کنم.»

سیستمی بسازید که متن مشتری را به یک Support Ticket ساختاریافته تبدیل کند. خروجی باید شامل این موارد باشد:

category
priority
sentiment
summary
customer_problem
suggested_action
needs_human_agent

مثلاً category می‌تواند یکی از این موارد باشد: authentication / payment / technical / account / other

و priority: low / medium / high / critical

الزامات فنی

  • ChatPromptTemplate
  • SystemMessage
  • HumanMessage
  • Pydantic
  • with_structured_output
  • init_chat_model

الزامات Prompt Engineering

  • نقش مدل را مشخص کند.
  • Task را مرحله‌بندی یا شفاف‌سازی کند.
  • متن مشتری را با delimiter جدا کند.
  • معیار مشخصی برای تشخیص priority ارائه دهد.
  • از مدل بخواهد بر اساس شواهد موجود در متن تصمیم بگیرد.
  • خروجی را دقیقاً مطابق schema تولید کند.

تست

حداقل ۵ پیام متفاوت برای سیستم بنویسید: مشکل Login، مشکل پرداخت، مشکل فنی، یک سؤال ساده، یک پیام عصبانی مشتری.

هدف این تمرین این است که ببینید آیا طراحی Prompt شما روی کیفیت classification تأثیر می‌گذارد یا نه.

رفرنس: 03_02-Guidelines-for-Prompting.ipynb و 04_01-Models_Messages_StructuredOutput.ipynb
تمرین ۴

تولید محتوای فنی با Prompt Template

فرض کنید یک تیم فنی می‌خواهد برای موضوعات مختلف، محتوای آموزشی تولید کند. تابعی بسازید:

generate_technical_content(
    topic,
    audience,
    difficulty,
    language,
    content_type
)

مثلاً:

generate_technical_content(
    topic="RAG",
    audience="Python developers",
    difficulty="intermediate",
    language="Persian",
    content_type="LinkedIn post"
)

content_type می‌تواند مثلاً یکی از این موارد باشد: LinkedIn post / Tutorial / Short explanation / Cheat sheet

الزامات فنی

  • init_chat_model
  • ChatPromptTemplate
  • Pydantic

خروجی را به شکل ساختاریافته برگردانید:

title
content
key_points
target_audience
suggested_hashtags

نکته مهم

یک Prompt ثابت برای همه حالت‌ها ننویسید که فقط متغیرها را داخل آن قرار دهید؛ طراحی Prompt باید به شکلی باشد که مدل واقعاً تفاوت بین beginner / intermediate و LinkedIn post / Tutorial را در خروجی لحاظ کند.

تمرین ۵

ساخت دستیار تحلیل جلسه

فرض کنید متن transcript یک جلسه فنی در اختیار شماست و می‌خواهید آن را به یک گزارش قابل استفاده برای تیم تبدیل کنید. تابعی بنویسید:

analyze_meeting(transcript: str)

که transcript را دریافت کند و خروجی زیر را تولید کند:

summary
decisions
action_items
open_questions
mentioned_people
mentioned_projects
next_steps

برای action_items حداقل این اطلاعات را داشته باشید:

task
owner
deadline

نکته مهم

اگر در transcript مشخص نشده باشد چه کسی مسئول یک Task است یا deadline مشخصی وجود نداشته باشد، مدل نباید آن را حدس بزند. مثلاً:

owner = None
deadline = None

الزامات فنی

  • init_chat_model
  • ChatPromptTemplate
  • Pydantic
  • with_structured_output

الزامات Prompt Engineering

  • Role مشخص داشته باشد.
  • هدف Task کاملاً مشخص باشد.
  • Transcript با delimiter جدا شود.
  • درباره عدم hallucination دستور واضح داشته باشد.
  • قوانین استخراج action_items را مشخص کند.
  • Format خروجی مشخص باشد.
  • از مدل بخواهد بین «تصمیم گرفته‌شده» و «پیشنهاد مطرح‌شده» تفاوت بگذارد.

بخش Iterative

ابتدا یک Prompt اولیه بنویسید و اجرا کنید. سپس حداقل دو مشکل واقعی خروجی را پیدا کنید و Prompt را اصلاح کنید.

در نهایت سه نسخه زیر را در Notebook نگه دارید: Prompt V1، Prompt V2، Prompt V3 و کوتاه توضیح دهید که در هر نسخه چه چیزی را تغییر داده‌اید و چرا.
